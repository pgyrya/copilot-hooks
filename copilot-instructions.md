# Guidelines

## Project Context

Read and follow `AGENTS.md`, `README.md`, `CONTRIBUTING.md` in the target repository before making changes. Inspect existing examples to align with established patterns.

## General Principles

- Plan before acting — infer intent, review dependencies, optimize scope and define success criteria before making changes.
- Track tasks with session-transient tools (todo list or session memory). Keep items clear, actionable, and updated.
- Log bugs, unresolved issues, and improvement ideas in the repository's established documentation locations.

## Ensure Quality

- Verify every change against the user request, its intent, and the repository context. Call out incompletion explicitly rather than shipping partial work.
- See the QC skill for the full review and pre-mortem workflow.

## Keep Documentation Updated

- Document key decisions and rationale.
- Choose location that is aligned with the project practices.
- Use progressive disclosure: high-level concepts at top level, detailed references linked from there (prefer clickable links in markdown).
- Prefer links over embedded copies — duplicated content diverges.
- Document where information lives, not what it says (content changes; locations are stable).
